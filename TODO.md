# 📋 План розробки Telegram-бота для пошуку вакансій (Job Finder Bot)

Цей файл містить покроковий план створення асинхронного Telegram-бота на базі **Aiogram 3.x** та **FastAPI** за архітектурою **Serverless (Webhooks)**. 
Бот виступає мікросервісом і працює з уже наявною конфігурацією бази даних **Supabase**.

- [ ] **2.1. Віртуальне середовище та залежності**
  - [ ] Ініціалізувати `venv` (`python -m venv venv`) та активувати його.

    * `pydantic-settings` або `python-dotenv` (для конфігів)
- [ ] **2.2. Створення структури мікросервісу**
  - [ ] Створити архітектуру пакетів:
    ```text
    ├── src/
    │   ├── handlers/       # Обробники команд (start, help, filters)
    │   ├── middlewares/    # Мідлварі (авто-перевірка юзера в БД)
    │   ├── states/         # FSM (стани для опитування по фільтрах)
    │   ├── database.py     # Модуль підключення до наявної Supabase
    │   └── main.py         # Точка входу (FastAPI + Webhook handler)
    ```

## 🛠️ Етап 3: Розробка клієнтської логіки (Aiogram 3 + Supabase)
- [ ] **3.1. Інтеграція з наявною БД (`database.py`)**
  - [ ] Налаштувати асинхронний клієнт Supabase, використовуючи змінні оточення.
  - [ ] Написати функції-обгортки для взаємодії з наявними таблицями:
    * `is_user_registered(user_id)` — перевірка наявності ID.
    * `register_user(user_id, username)` — створення нового рядка.
    * `update_user_filters(user_id, data)` — запис/оновлення фільтрів пошуку.
    * `delete_user_subscription(user_id)` — відписка або видалення фільтрів.
- [ ] **3.2. Автоматичний перехват запитів (Middleware)**
  - [ ] Написати `OuterMiddleware` в `middlewares/db.py`. При кожному тригері від користувача перевіряти його статус в Supabase.
  - [ ] Якщо користувач новий — автоматично викликати `register_user`.
- [ ] **3.3. Команди користувача (`handlers/`)**
  - [ ] `/start` — вітальне повідомлення, перевірка реєстрації через мідлварь, вивід Inline-кнопок ("Налаштувати пошук", "Мої фільтри").
  - [ ] `/help` — довідка про те, як працює сервіс пошуку вакансій.
- [ ] **3.4. Машина станів для збору фільтрів (FSM)**
  - [ ] В `states/filters.py` створити клас `FilterStates(StatesGroup)` відповідно до наявних полів у вашій БД (наприклад: `waiting_for_keywords`, `waiting_for_city`, `waiting_for_experience`).
  - [ ] Реалізувати покроковий діалог з користувачем за допомогою Inline-клавіатур або текстових відповідей.
  - [ ] **Фінал станів:** Отримати згрупований `state.get_data()`, відправити його в Supabase через `update_user_filters()` і закрити стан (`state.clear()`).
